# 「加载失败：主库无 favorites 表」是怎么回事

> 出现在：**分组提取 APK** 页面。v1.1.2 已修复。

## 一、不是你的手机坏了，是代码把表名写死了

分组提取需要读桌面数据库里的「条目表」——每条记录 = 桌面上的一个图标/文件夹，
`container` 列说明它在哪（桌面 / Dock / 某个文件夹里），`intent` 列说明它指向哪个应用。

AOSP 原生桌面和小米桌面这张表都叫 **`favorites`**，所以 v1.1.1 及以前直接写死：

```java
if (!hasTable(db, "favorites")) {
    return new Result(false, "主库无 favorites 表", null, null);
}
```

但 ColorOS 的「系统桌面」是深度改过的分支，不同机型/版本的实情可能是：

| 差异 | 举例 |
|---|---|
| 表名不同 | `favorites` / `iteminfo` / `homeitem` / `workspace_items` |
| 库文件不同 | 条目表和屏幕表可能不在同一个 `.db` 里；也可能主库不是最大的那个 |
| 列名不同 | `container` vs `containerId`；`cellX` vs `cell_x` vs `posX`；`intent` vs `componentName` |

只要命中任意一条，旧代码就判定「主库无 favorites 表」直接放弃。
**备份和恢复不受影响**（它们是整库文件级拷贝，不认识表结构也能用），**只有分组提取会挂**。

## 二、v1.1.2 怎么改的

不再写死任何表名/列名，改成「按结构识别」：

1. **跨所有 `.db` 扫描**（不再只看打分最高的那个主库）；
2. 找到同时具备 **主键列 + 容器列 + 组件列** 三件套的表就视为候选；
3. 用候选列名表做**大小写不敏感**匹配（`_id/id/itemId`、`container/containerId/parentId/folderId`、
   `intent/intentUri/componentName`、`screen/screenId/page`、`cellX/cell_x/posX/column`…），
   匹配不到再做包含式模糊匹配；
4. 多张表都像时按表名打分（含 `favorit` +12、含 `item` +6、含 `home/desktop/workspace` +5、
   有 screen 列 +3、有坐标列 +2），取最高分；
5. 读出来的包名还兼容「`com.foo/com.foo.MainActivity` 直接存成组件字符串」这种写法。

识别成功时状态栏会写：`共 N 个应用（条目表 xxx）`，操作日志里也会打印
`条目表: 库名 / 表名 列: id=… title=… intent=… container=…`。**这两行告诉我表名，我就能确认。**

## 三、如果 v1.1.2 还是认不出来

分组提取页右上角多了个 **「导出表结构」** 按钮，点它会：

- 扫描桌面 `databases` 目录下**每个** `.db`；
- 列出每张表的**表名、行数、全部列名**；
- 顺便标注它识别到的条目表和列映射。

弹窗里点「复制全部」，把那段文本发回来即可——照着这个我能一次改对，不用再猜。

> 想自己在电脑上看也行（免 root 的目录也能读，但要 root 才能进 `/data/data`）：
> ```bash
> adb shell su -c "ls -l /data/data/com.android.launcher/databases/"
> adb shell su -c "sqlite3 /data/data/com.android.launcher/databases/launcher.db '.tables'"
> ```
> 如果没有 `sqlite3`，用「导出表结构」按钮最省事。

## 四、和备份/恢复的关系（重要）

| 功能 | 依赖表结构吗 | 说明 |
|---|---|---|
| 备份 | ❌ 不依赖 | 整库 +`-wal` +一致性快照，全量拷贝 |
| 恢复 | ❌ 不依赖 | 杀桌面 → 覆盖文件 → 修属主/SELinux → 拉起 |
| 布局指纹 | 半依赖 | 认不出时自动退化为「对全部表的排版相关列做哈希」 |
| CSV 导出 | 半依赖 | 认不出时少一张 `favorites.csv`，其它表照导 |
| **分组提取 APK** | ✅ 依赖 | 需要读条目表才知道「哪个应用属于哪个文件夹」 |

所以出现这个报错时，**你的备份数据没有任何问题**，只是分组视图加载不出来。
