# 分组提取：为什么这些地方这么设计（v1.1.3）

## 1. 提取全部失败，报 `Invalid URI: content://.../tree/...`

旧版只走 **SAF**（系统文件选择器给的 `content://` 授权 URI）这一条路。
这套机制在 ColorOS 上很脆：

- 选择器返回的 URI 可能是 **tree** 形式（`…/tree/primary%3ADownload%2F备份`），
  也可能因为选的是子目录/上次保存的是 document 形式而变成 `…/tree/xxx/document/yyy`；
- 打开文件时如果拿后者去调 `DocumentsContract.getTreeDocumentId()`，就会抛
  `IllegalArgumentException: Invalid URI: …` —— 你日志里 11 条全挂就是这个；
- 即便 URI 形式对，还有持久化授权丢失、目录被系统判为不可写等问题。

**v1.1.3 的改法：默认不再依赖 SAF。**

现在的主路径是 **root 直写绝对路径**：

```
mkdir -p '/storage/emulated/0/Download/备份/工具'
cp -f  <源APK>  '/storage/emulated/0/Download/备份/工具/xxx.apk'
stat -c %s       →  用大小校验是否写全
```

root 会话本来就为「恢复」授权过，用它写文件：
- 不受 SAF 任何限制，**任意目录都能写，非空目录也可以**；
- 自动 `mkdir -p` 建目录；
- 写完立刻用 `stat` 校验字节数，写残了会明确报错；
- SAF 仍保留为备用：root 失败时自动再试 SAF（且会把 URI 规范化后再用）。

## 2. 为什么「只能选空目录」

这是 **Android 11+ 系统文件选择器（DocumentsUI）自己的限制**，不是本 App 加的：

- `Download` 根目录、内部存储根目录会被系统判定为「不适合授权」，
  按钮灰掉或弹「为了您的隐私，请选择其他文件夹」；
- 部分 ROM 上这个判断还会牵连到刚建的空目录状态，看起来就像「只有空目录能选」。

所以别再跟选择器较劲了：**直接在上面那个输入框里填路径**（默认
`/storage/emulated/0/Download`），点「保存路径」即可，写任意目录都行。
「系统选择器（SAF）」按钮还留着，给不想用 root 的场合。

## 3. 每个分组建独立文件夹

「**每个分组建独立文件夹**」开关（默认开）：

```
/storage/emulated/0/Download/<分组名>/<按命名规则生成的文件名>.apk
```

关掉就是全部平铺在目标目录里。分组名里的 `/ \ : * ? " < > |` 会自动替换成 `_`。

## 4. 桌面上叫「交通导航」，这里却显示 Navigation

原因是两个名字的来源不同：

| 来源 | 说明 |
|---|---|
| 桌面数据库 `title` 列 | 建库/装应用时写入的**旧标注**，很多 ROM 之后就不再更新 |
| `PackageManager` 的应用本地化名称 | 应用自己声明、**跟随系统语言**的名字，桌面渲染图标时用的就是它 |

旧版只显示数据库里那个（于是出现 `Navigation`）。v1.1.3 起：

- **主名称 = 系统本地化名称**（和桌面一致，`交通导航`）；
- 两

者不一致时，第二行会写成 `包名 · 桌面标注：Navigation`，信息不丢；
- 命名规则里的 `{AN}` 用的也是**主名称**，导出的文件名和桌面叫法一致。

## 5. 默认状态：全部折叠 + 全部不选

- 分组默认**全部折叠**，只显示 `▸ 分组名（数量）`；点标题展开/收起；
- 应用默认**全部不选**，点一行即勾选；分组右侧「整组选/取消」一次性处理该组；
- 顶栏还有 `展开全部` / `全部折叠` / `全选` / `全不选`。

## 6. 卡顿

旧版每次勾选都会 `removeAllViews()` 重建整页，并且同步调用
`PackageManager.getApplicationIcon()`（每次几十毫秒），几十个应用就是明显掉帧。

v1.1.3：
- 图标**异步加载 + 缓存**（2 线程池，加载完再贴上去）；
- 勾选只更新复选框和计数，**不再重建列表**；
- 默认折叠，首屏只渲染分组标题（视图数量从几百降到几十）。
