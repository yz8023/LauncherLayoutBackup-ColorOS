# v1.2.1：修回 v1.2.0 丢掉的提取页功能 + 定版视觉

## 1. 为什么 v1.2.0 的「提取」页既卡、又没了折叠

v1.2.0 打包时，`PageExtract.java` 被一份**旧版本**覆盖了（构建工作区的文件被回滚到 v1.1.2 之前的状态），
所以那一版实际装进去的是旧实现：

| 现象 | 旧实现的代码 | 后果 |
|---|---|---|
| 折叠功能没了 | 没有 `mExpanded`，所有分组一次性全展开 | 几十上百个应用全部铺开 |
| 点「提取」就卡 | `rebuildList()` 里对**每个应用同步**调 `getApplicationIcon()` | 主线程被包管理器拖住数百毫秒 |
| 名字又变回 `Navigation` | 同步查名字的那套逻辑 | 和桌面不一致 |

同时被覆盖掉的还有：root 直写、同名文件夹区分、表结构导出（`ACTION_SCHEMA`）、
跨库识别条目表 —— 也就是 v1.1.2~v1.1.4 的修复全被打回去了。

### 修法

1. 从 v1.1.4 的提交（`9fbb5d7`）把 6 个文件原样恢复：
   `PageExtract` `BackupEngine` `Bridge` `LauncherReceiver` `Const` `BaseActivity`；
2. 在此之上再做**异步化**，把最后一点卡顿也去掉：
   - 解析分组时**不再**逐个查 `PackageManager`，先用数据库里的标注顶上；
   - 展开某个分组时才异步查系统名称、图标，查到就回填那一行（主线程零阻塞）；
   - 生成文件名时（后台线程）才取最终显示名，所以 `{AN}` 依然是桌面上的名字。
3. 新增 `scripts/preflight.sh`：发布前自检 20 项关键修复是否还在，
   任何一项被回退就拒绝发布 —— 这种事不会再发生第二次。

## 2. 视觉定版：中性底 + 克制的绿

你让我自己定，我选了**「系统设置同款」的中性风格**，绿色只做强调，不再整片铺：

| 项目 | 改动 |
|---|---|
| 页面底色 | `#F4F6F2`（深色 `#101310`），比原来更中性，卡片浮起来更明显 |
| 卡片 | 纯白 + **0.7dp 细描边**，去掉阴影（阴影在 OLED 上会发灰、边缘发脏） |
| 圆角 | 卡片 18dp、按钮 22dp（不变） |
| 主色 | 绿收敛到 `#1B6B35`（深色 `#7FD68F`），只用于主按钮、状态点、「最新」胶囊 |
| 页面标题 | 30sp → **26sp**，medium 字重 + 轻微负字距 |
| 分组小标题 | 由绿色 13sp 改成 **灰 11.5sp + 0.06 字距**（像 iOS/设置页那种小标题） |
| 状态 | 一行：圆点（绿/红）+ 文案 + 网格胶囊 |

这样视觉重心就落在「内容 + 一个主按钮」上，而不是满屏绿块。
